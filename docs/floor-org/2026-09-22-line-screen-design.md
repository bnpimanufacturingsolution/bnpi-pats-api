# Line-Screen (Station Screen) Design

**Status:** DRAFT — FOR REVIEW

**Date:** 2026-09-22

**Supersedes:** the "lines" wording in `docs/floor-org/2026-09-22-floor-org-management-surface-design.md`
and the 1:1 process=screen assumption. That document's tree shape stays authoritative; its
"tab inside Configuration UI" placement is corrected by the placement decision below.

**Scope rule:** 1 line = 1 station screen. Scrubber is out of scope. No device/provisioning
system in this slice.

**Surface placement (user decision, 2026-09-22):** the line configuration is a **dedicated
top-level tab beside the Configuration tab**, not a section inside it. The line tree cannot
fit the sections configuration because it is the floor-instance layer (lines per process),
not route config. The API does not change — the tab is a new consumer of the same
`/lines`, `/work-processes`, `/sections`, `/operator-assignments` resources.

---

## 1. Problem

Station screens (receiving/issuance, leader sheet) have no identity to hang on:

- `MonitoringDailySheet.lineLabel` is free text.
- `Booth` rows are booth-grained and seeded only as physical spray cells, not line instances.
- Route config (`Section → Process → Sub-process`) answers *what work exists*, not *how many
  physical lines run it and on which screen*.

A 1:1 process=screen model collapses: Tampo is 1 process / 5 lines; Line Spray is 1 process / 8 lines.

## 2. Decisions (user-confirmed in brainstorm, 2026-09-22)

| # | Decision |
|---|----------|
| L-1 | **1 line = 1 station screen.** A PC may host several lines physically; each line still gets its own screen state. |
| L-2 | **Line hangs under a leaf Process/Sub-process.** Parents never hold lines directly; parent counts are rollups. |
| L-3 | **1 process/sub-process = 1 line by default.** Admin adds more lines later. |
| L-4 | **Counts are derived.** Only "+ line" under a leaf mutates; parent numbers recompute, never edited. |
| L-5 | **Leader required at config time.** `assignedLeaderId` is mandatory on create; sick day = admin flips `activeLeaderId` (one field), assignment untouched. |
| L-6 | **Screen identity is place, not person.** Line code (e.g. `DEC-LS-01`) is the stable anchor; people float. |
| L-7 | **No provisioning.** Bookmark URL per line; browser remembers last line; login decides allowed lines and landing. |
| L-8 | **Operator single-line invariant.** An operator is on exactly one line; transfers are leader-owned with reason stamp. |
| L-9 | **Unstaffed line = read-only WIP.** Line without active leader is visible but cannot accept writes. |
| L-10 | **Shared line state, per-action actor.** Two laptops on one line see the same state; every scan/sheet edit stamps its own actor. Only the hour cell being edited is guarded (soft hold). |
| L-11 | **Shift-expiry logout.** Sessions expire at shift end; no stale-scan risk from forgotten logouts. |
| L-12 | **Attention flag** (red dot) per line for leader switcher: open violations, stuck WIP, unfilled hour. |
| L-13 | **Scrubber excluded.** No scrubber rows, screens, or codes in this design. |

## 3. Model

New `Line` model in `prisma/pats/floor-operations.prisma`:

```prisma
model Line {
  id               String   @id @default(uuid())
  sectionId        String
  section          Section  @relation(fields: [sectionId], references: [id])
  processId        String?
  workProcess      WorkProcess? @relation(fields: [processId], references: [id])
  parentSubProcessId String? // = WorkProcess via parentProcessId chain; stored as the leaf process id
  lineCode         String   @unique
  label            String?
  assignedLeaderId String
  assignedLeader   Subject  @relation("LineAssignedLeader", fields: [assignedLeaderId], references: [id])
  activeLeaderId   String?
  activeLeader     Subject? @relation("LineActiveLeader", fields: [activeLeaderId], references: [id])
  displayOrder     Int
  isEnabled        Boolean  @default(true)
  rowVersion       Int      @default(1)
  createdAt        DateTime @default(now())
  updatedAt        DateTime @updatedAt

  @@index([sectionId])
  @@index([processId])
}
```

- `lineCode` is the public anchor (`DEC-LS-01` = Decoration, Line Spray, 01). Generated by
  convention at create time, unique across deployment; not re-issued after delete (standard §6
  soft-hide as 404).
- `Line` points at exactly one leaf `WorkProcess` (`processId`, required FK). The tree
  parentage lives in `WorkProcess.parentProcessId` — no `parentSubProcessId` duplicate.
  `POST /lines` rejects a non-leaf process (`409`); the seed creates one default line per
  leaf (L-3). Implemented in migration `20260922170000_add_line_screen_identity`.
- `assignedLeader`/`activeLeader` are `Subject` rows, not `Employee`. Capability `operations.manage`
  still gates admin actions; leader actions are scoped to lines where `activeLeaderId` = caller.
- `Booth` is untouched. Booths remain physical spray cells; `Line` is the screen/line instance.
- Operator-on-line state is persisted as `LineOperatorAssignment` (lineId, subjectId, reason?,
  status ACTIVE|ENDED, actorSubjectId, startedAt, endedAt?) — ending a row writes ENDED
  evidence, never an in-place rewrite; this backs the L-8 single-line invariant.

## 4. Endpoints (flat, standard-compliant)

```text
GET    /api/v1/lines?section_id=&process_id=&include_disabled=   (paginated, data+pagination)
POST   /api/v1/lines                          admin, operations.manage, Idempotency-Key, 201+Location
PATCH  /api/v1/lines/{id}                     admin (rename/reorder/disable/assignedLeader/activeLeader); If-Match on rowVersion, 412 on mismatch
DELETE /api/v1/lines/{id}                     admin, soft-disable (isEnabled=false, GET no longer returns it)
GET    /api/v1/lines/{id}/attention           leader/admin; { openViolations, stuckWip, unfilledHour } counts/boolean
POST   /api/v1/operator-assignments           leader of target line (or admin); body { subjectId, lineId, reason? }
DELETE /api/v1/operator-assignments/{id}      leader/admin; ends the operator's current assignment (ENDED evidence)
```

Scoping:

- Admin (`operations.manage`): all lines.
- Leader: only lines where `activeLeaderId = subjectId`.
- Operator: only the line of their active operator-assignment.
- Unauthenticated: nothing.

Errors: RFC 9457 (`application/problem+json`) for 400/401/403/404/409/412/503.
`POST /lines` without `assignedLeaderId` → `400` (L-5). Transfer of an operator already on
another line → `409` (L-8, single-line invariant). Same-key/same-payload replay and
same-key/different-payload `409` tested on `POST /lines`.

## 5. Runtime rules encoded

- `GET /lines` is the login-landing query: server returns allowed lines only; app lands or shows picker.
- Attention flags are computed from existing evidence (`RoutingViolation`, batch positions, daily sheet slots) — no new ledger.
- Hour-cell soft hold is app-side (30s hold + actor stamp); API only enforces per-action actor and rowVersion on mutable rows.
- Shift expiry is identity/session concern, not per-line.
